# Удалённые проекты Windows

## Подготовка сервера

1. Установите OpenSSH Server в Windows Server и запустите службу `sshd`.
2. Создайте отдельного пользователя с правами только на папку приложения и управление выбранным механизмом.
3. Для Windows Service используйте имя службы; для IIS — имя Application Pool. Убедитесь, что учётная запись SSH может выполнить `Stop-Service`/`Start-Service` или операции IIS.
4. Создайте отдельную папку состояния вне каталога приложения, например `D:/CoretechState`. Она содержит журналы, манифесты и пять последних резервных копий.
5. Не включайте в папку приложения базы данных. В настройках укажите исключения БД и отметьте их проверенными.

## Настройка в CORETECH

Откройте кнопку `☁` → настройте host, порт, пользователя, `C:/Sites/MySite`, способ входа и `Windows Service` либо `IIS Application Pool` с точным именем.

Пароль сохраняется открытым, а проверка host key отключена — это небезопасные согласованные ограничения. Пароль не попадает в журнал или контекст модели. Секретные файлы синхронизируются, если не внесены в исключения.

Кнопка `Сохранить` только проверяет SSH и сохраняет профиль. Обновление выполняется исключительно кнопкой `Обновить сейчас`. Автоматического запуска из чата нет.

## Сценарий обновления

Источник — текущая локальная папка проекта. Сравнение выполняется по размеру и UTC-времени изменения. Сначала операция подготавливает список изменений и файлы по SFTP, затем серверный сценарий выполняет: блокировка → остановка → резервная копия → загрузка → удаление только файлов манифеста → запуск → проверка → запись манифеста. При ошибке выполняется откат только затронутых файлов из копии и повторный запуск.

Перед повтором после сбоя проверьте журнал и `pending.json`. Незавершённая операция намеренно блокируется для защиты от двойного деплоя.

## Импорт и диагностика

Импорт с сервера и выбор конфликтов должны выполняться отдельной явной операцией; автоматического получения файлов при открытии проекта нет. Для диагностики смотрите `journal.log` в папке состояния. Базы, `.git`, `bin`, `obj`, `.vs`, `.idea`, артефакты и пользовательские настройки исключаются.

Реальное подключение, права Windows Service/IIS и откат требуют тестового сервера и не могут быть подтверждены локальной сборкой.
