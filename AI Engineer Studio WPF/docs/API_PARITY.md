# Единая логика API

## Исследование

Обычная и WebSiteDev-версии используют одинаковую схему чата: WPF передаёт ключ, Base URL, модель и историю в локальный `neural_bridge.py`; bridge создаёт OpenAI-compatible клиент. Настройки намеренно разделены: обычная версия хранит их в `%APPDATA%\\AIEngineerStudio`, WebSiteDev — в `%APPDATA%\\AIEngineerStudio.WebSiteDev`.

Было найдено расхождение не в основном чате, а в дополнительных HTTP-запросах: баланс и вложения формировали URL и `Authorization` отдельно и не применяли одинаковую очистку ключа/URL.

## Изменения

Добавлен одинаковый `src/Infrastructure/Services/ApiConfiguration.cs` в оба проекта:

- удаляет пробелы, кавычки и повторный `Bearer` из ключа;
- нормализует Base URL и убирает случайный `/chat/completions`;
- создаёт одинаковые заголовки `Authorization: Bearer` и `x-api-key`;
- используется балансом и отправкой вложений;
- payload чата передаёт уже нормализованные значения.

Bridge-файлы обеих версий уже содержат одинаковую нормализацию ключа/URL и одинаковое создание клиента. Ограничение запуска dev-серверов через `execute_command` остаётся только в WebSiteDev и относится к веб-инструментам, а не к API-авторизации.

## Проверки

Выполнены:

- сравнение SHA/дифф реализации до изменений;
- автоматическая проверка одинакового `ApiConfiguration`;
- сборка обычного проекта: успешно, 0 ошибок/предупреждений;
- сборка WebSiteDev: успешно, 0 ошибок/предупреждений.

Реальный API-запрос и проверка ключа не выполнялись. Поэтому совпадение логики подтверждено локально, но доступность конкретного ключа и совместимость endpoint должны проверяться отдельно. Секреты в отчёт не записывались.
