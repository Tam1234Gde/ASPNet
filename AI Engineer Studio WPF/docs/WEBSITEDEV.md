# WebSiteDev

## Что добавлено

`WebSiteDev/AIEngineerStudio.WebSiteDev.csproj` — отдельный WPF-проект в `AIEngineerStudio.Wpf.slnx`. Исходный `AIEngineerStudio.Wpf` не заменён. WebSiteDev использует отдельное имя сборки `CORETECH.AIEngineerStudio.WebSiteDev`, отдельное хранилище настроек `AIEngineerStudio.WebSiteDev` и заголовок окна.

Панель `Web` доступна в WebSiteDev. Стек и команды сначала выбираются/проверяются пользователем, затем сохраняются в проекте. Пресеты первой версии:

- статический HTML/CSS/JS — `python -m http.server`;
- npm/Vite/React/Vue — `npm ci`, `npm run build`, `npm run dev ...`;
- ASP.NET Core — `dotnet restore`, `dotnet build --no-restore`, `dotnet run ...`;
- пользовательский стек — команды задаются вручную.

Пресет не устанавливает технологию и не запускается автоматически. Публикация SSH остаётся явным действием и использует существующий диалог удалённого проекта.

## Управление процессом

Dev-сервер запускается только через `WebProcess`, а не как конечная команда агента. Его stdout/stderr читаются асинхронно, журнал ограничен 250 строками, остановка использует `Kill(entireProcessTree: true)` только для дерева конкретного запуска. Свободный порт проверяется до запуска; занятый чужой порт не перехватывается. Готовность подтверждается HTTP-ответом, а не только наличием процесса.

Конечные команды имеют таймаут и отмену. В `neural_bridge.py` агентный цикл ограничен 40 шагами, команды с признаками dev-сервера отклоняются с предложением использовать панель Web. Это устранение бесконечного ожидания является защитным ограничением; исходную причину старого зависания без воспроизведения нельзя считать установленной.

Рабочая папка блокируется межпроцессным lease-файлом. Это предотвращает молчаливую одновременную запись двух редакций в одну папку. Настройки и история экземпляров изолированы.

- `dotnet build AIEngineerStudio.Wpf.slnx --configuration Release` — успешно, 0 ошибок, 0 предупреждений.
- Синтаксически проверена структура изменений в Python через запуск build-процесса; сетевой API не вызывался.
- В сборке присутствуют два разных DLL: `AIEngineerStudio.Wpf.dll` и `CORETECH.AIEngineerStudio.WebSiteDev.dll`.

Причина исходного зависания не доказана профилированием. Успешная сборка не означает готовность сайта или успешность публикации.
