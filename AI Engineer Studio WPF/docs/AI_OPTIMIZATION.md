# Оптимизация контекста AI Engineer Studio

## Реализовано

- Проектный индекс создаётся в `<проект>/.coretech/<вариант>/` и изолирован для desktop/WebSiteDev.
- Индекс обновляется в фоне после открытия проекта; служебные каталоги и секретные имена исключены.
- Выбор модели можно отключить в настройках. При включённом режиме мост сообщает выбранную модель и причину.
- Для чата «Общение» отправляется хвост истории (32 сообщения), а файлы выбираются индексом по словам запроса. Это ограничивает UI-запрос, но не меняет сохранённую историю.
- Повторное чтение файлов в `conversation_project.py` кэшируется по `mtime_ns + size`; кэш ограничен 16 файлами.
- Старые данные должны использоваться как справочные и подгружаться по необходимости; существующая полная история проекта сохраняется.

## Проверка

Синтаксис `context_optimizer.py` и bridge проверен `py_compile`. Основная и WebSiteDev версии собраны в отдельные каталоги `artifacts/optimization-main` и `artifacts/optimization-web` без ошибок.

## Ограничения

- Реальное число токенов, задержка API и память до/после не измерялись: нужен доступный API и запуск UI с одинаковым набором данных.
- Выбор экономичной модели проверяется через `/models`, иначе остаётся ручная модель.
- Полная интеграция extractive-сводок и дополнительных tool-схем в bridge пока не включена; старые сообщения не удаляются и не теряются.
- Текущий UI не выводит отдельную панель метрик; уведомления оптимизации приходят как bridge-события и требуют обработки интерфейсом.
