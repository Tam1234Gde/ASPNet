# Оптимизация чатов — фактическое состояние

## Реализовано
- StackPanel внутри внешнего ScrollViewer заменён ChatMessageList (ListBox, Recycling, Pixel scroll, буфер 0.5 страницы).
- В списке хранятся фабрики строк, а не заранее построенные UIElement. Markdown, вложения и карточки создаются при материализации контейнера; при очистке контейнера Content освобождается.
- Начальная порция 50 сообщений, подгрузка по 50 вверх с защитой от повторного входа и восстановлением якоря по объекту строки и пиксельному смещению.
- Отложенная прокрутка защищена поколением представления. Автопрокрутка только у конца; кнопка перехода к новым сообщениям.
- Ответ общения добавляется без перестройки списка. Мультивыбор записывает промежуточное состояние в модель карточки.
- Чтение и JSON-десериализация при выборе/редактировании проекта вынесены в Task.Run; повторное открытие и отправка во время загрузки блокируются.
- Правила контекста API не изменены, полная история остаётся доступна обоим существующим путям подготовки запросов.

## Измерения
Стенд: artifacts/chat-perf, синтетическая история с Markdown и блоком C#, область 650x650. Один STA-процесс, текущий MarkdownRenderer, старый способ воспроизведён через ScrollViewer + StackPanel с созданием всех карточек. Это не время полного запуска или дискового открытия проекта. Значения одного прогона; не SLA.

| Сообщения | Старый render/layout, мс | Новый, мс | Старые контейнеры | Новые |
|---:|---:|---:|---:|---:|
|50|370|37|50|4|
|500|3689|34|500|4|
|2000|8355|20|2000|4|

В этом прогоне прирост managed heap до сборки мусора для 2000 сообщений: ~343.5 MB против ~3.4 MB. Это не working set и не retained memory. Повторные прогоны и исходные результаты находятся в artifacts/chat-perf/*.txt. В тесте проверено, что контейнеры действительно существуют (не ноль) и их меньше 50; добавление старой страницы не меняет полную историю API.

## Ограничения / незавершённые пункты
- Дисковая история пока остаётся единым JSON; постраничного чтения с диска и миграции формата нет. Полная история и её модели остаются в памяти. SaveProject всё ещё синхронно сохраняет полный документ по сообщениям (не по токенам).
- Размер страницы 50 — предварительный, сравнительный подбор нескольких размеров ещё не выполнен.
- Bridge возвращает завершённый текст, токенного UI-стриминга в исследованном пути нет. Его реализация/батчинг не добавлены.
- Проверка якоря реализована, но отсутствие скачков при реальной прокрутке неодинаковых карточек не подтверждено ручным тестом.
- Не измерены полное открытие проекта, реальное переключение окон/проектов, input latency, retained memory.
- Не проведены live API, долгий soak-test, ручные действия с буфером обмена, передачей промптов и медиа. Существующие 15 тестов уточнения адаптированы к ListBox и запущены; проверки количества строк не заменяют проверки видимых кнопок.
- Исходники сохранены в backups/chat-performance, приложение пользователя не перезапускалось.

Таким образом устранено подтверждённое узкое место массового построения UI, но весь первоначальный план ещё не завершён.
